# Interview Notes

## 项目一句话介绍

这是一个面向安防知识问答场景的 RAG Demo，我把安防文档问答里的关键链路抽成了一个可展示的项目，既保留了可运行主链路，也补齐了 Milvus、OCR、BGE、LangGraph、Corrective RAG、Adaptive RAG 和 RAGAS 对应的架构模块。

## 业务背景怎么讲

安防场景里的知识通常分散在设备接入手册、告警处置规范、部署文档和历史排障案例中。传统关键词检索在复杂问题下效果不稳定，而通用大模型直接回答又容易出现幻觉，所以我设计了一个 RAG 问答系统，把安防知识结构化入库，再通过检索增强和工作流控制，让回答尽量基于证据生成。

## 系统链路怎么讲

可以按这条链路介绍：

1. 文档准备：将安防知识文档整理成知识源。
2. 文档切分：按章节和段落切分，超长内容再做语义补充分块。
3. 检索层：同时做 Dense 和 Sparse 两路检索，再融合排序。
4. 工作流层：根据问题语义，把请求路由到设备接入、告警处置或部署排障等知识域。
5. 评估层：对检索结果和最终回答做置信度判断。
6. 风控层：如果是高风险问题或低置信度回答，进入人工确认。
7. 输出层：返回最终答案，并附证据来源，增强可解释性。

## 代码结构怎么讲

- `app/chunking.py`
  - 负责章节分块和长文本二次切分
- `app/retrieval.py`
  - 负责本地 Dense/Sparse 混合检索实现
- `app/knowledge_base.py`
  - 负责知识库构建与统一搜索入口
- `app/workflow.py`
  - 负责路由、评估、人审和回答组织
- `app/api.py`
  - 负责 FastAPI 接口暴露
- `app/ingestion/`
  - 对应 PyMuPDF、Unstructured、Tesseract OCR 解析模块
- `app/embeddings/`
  - 对应 BGE 稠密向量和 BM25 稀疏检索模块
- `app/vectorstore/`
  - 对应 Milvus 集群、Dense/Sparse 双索引和 schema 设计
- `app/graph/`
  - 对应 LangGraph 风格节点、状态和中断蓝图
- `app/evaluation/`
  - 对应 Corrective RAG、Adaptive RAG 和 RAGAS 评估闭环
- `data/security_docs/`
  - 放安防样例知识文档

## 亮点怎么讲

### 1. 不是简单 FAQ，而是证据驱动问答

系统不会只做关键词匹配，而是先检索证据，再把多个命中片段组织成回答，并把来源一起返回。

### 2. 混合检索比单一路径更稳

安防文档里既有术语，也有流程描述。只用语义检索容易漏掉精确关键词，只用 BM25 又难处理同义表达，所以我把 Dense/Sparse 组合起来做融合排序。

### 3. 加了工作流和风控逻辑

我没有把它做成“一个 prompt 走到底”的系统，而是拆成了路由、检索、评估和人工确认几个阶段。这样更符合企业级问答系统的设计思路。

### 4. 可扩展到真实工程

当前 demo 用的是“主链路可运行 + 架构模块齐全”的版本：

- `deploy/docker-compose.milvus.yml` 展示了 Milvus 部署蓝图
- `app/ingestion/` 展示了文档解析链路接口
- `app/graph/` 展示了 LangGraph 风格工作流拆分
- `app/evaluation/` 展示了 Corrective / Adaptive / RAGAS 模块边界

## 如果面试官问：为什么没有直接接 Milvus / OCR / 大模型？

可以这样回答：

这个项目是面试展示型 demo，我优先保留了最能体现架构设计能力的主链路，而没有把外部依赖堆满。这样有两个好处：

1. 本地能稳定跑通，便于现场演示。
2. 核心抽象足够清晰，能说明我理解真实生产系统的关键模块和扩展方向。

如果需要接入真实工程，文档解析可以接 OCR 或 Unstructured，检索层可以切到 Milvus，工作流层可以切到 LangGraph，评估层可以接 RAGAS 或线上评测指标。

## 和 `智能安防知识问答平台.txt` 的匹配度

这个 Demo 和 txt 的关系已经从“核心方向一致”提升到“主要能力点都有对应模块，但部分模块仍是 blueprint”。

### 基本匹配的部分

- 安防知识问答业务背景
- 面向研发、实施、运维团队的问题定位场景
- 章节分块 + 语义补充分块
- Dense/Sparse 混合检索思想
- 工作流式问题路由
- 低置信度结果的人审机制

### 已补齐但仍是 blueprint 的部分

- txt 里写的是 Milvus 集群 + Docker，这个 demo 已补了 `vectorstore` 模块和部署文件，但默认运行时仍用本地检索器。
- txt 里写的是 PDF/PPT/Word/HTML/OCR 全链路，这个 demo 已补了 `ingestion` 模块，但默认运行时仍用 Markdown 样例文档。
- txt 里写的是 bge-large-zh-v1.5、DAAT、索引参数调优，这个 demo 已补了 `embeddings` 和 `milvus_schema` 模块，但默认运行时不强依赖这些外部组件。
- txt 里写的是 Corrective RAG / Adaptive RAG / RAGAS 闭环，这个 demo 已补了 `evaluation` 模块，但默认运行时还是轻量评估逻辑。

### 不完全匹配的地方

如果严格按 txt 的“工程落地细节”逐项对照，这个 demo 仍不是完整生产复刻版。它更像是：

“用一个能跑主链路、又能展示完整架构拆分的项目，把原始描述中的关键能力全部落到模块层面。”

## 你可以怎么收尾

最后可以这样总结：

我这个 demo 重点不是追求把所有外部组件都接满，而是把安防 RAG 系统里最核心的工程抽象跑通，包括知识组织、混合检索、工作流控制、风险拦截和可解释输出。这样既能展示技术理解，也方便后续平滑扩展到真实生产架构。
