# 实现说明

这个 Demo 对应的是“基于 GME 模型的安防多模态 RAG”项目，而不是之前的安防 FAQ / 工作流 demo。

## 这里怎么理解

你可以把这套代码看成 8 个连续阶段：

1. `parser_demo.py`
   - 模拟 Dots.OCR / Unstructured / OCR 之后的统一解析结果
2. `chunker_demo.py`
   - 模拟章节分块 + SemanticChunker
3. `embedding_demo.py`
   - 模拟 GME 统一向量空间
4. `index_demo.py`
   - 模拟 Dense + Sparse 混合检索
5. `memory_demo.py`
   - 模拟 Redis 短期记忆 + 长期记忆回写
6. `evaluation_demo.py`
   - 模拟 Corrective RAG + Adaptive RAG + RAGAS
7. `workflow_demo.py`
   - 把这些模块串成一条多模态问答链路
8. `api.py`
   - 提供最小 API 入口，方便从结果角度理解系统输出

## 为什么这样设计

因为你面试时重点讲的是项目方案和你的工作内容，而不是现场展示复杂依赖是否能完全启动。所以这套 Demo 优先保证：

- 模块边界清晰
- 名称和职责与项目文档一致
- 能顺着代码把整条链路讲通
- 每个阶段都能对应到项目描述中的一条能力点

## 哪些是 mock

- GME 向量由可解释的哈希向量模拟
- Milvus 检索由本地索引模拟
- Redis 由进程内存模拟
- Dots.OCR 由 markdown 中的 `IMAGE_REF` / `TABLE_REF` 标记模拟
- RAGAS 由规则分数模拟

## 哪些是关键表达

面试时你可以强调：

1. 多模态知识不是只做图片 OCR，而是把文本、图片、图文对统一成可检索知识单元。
2. GME 的价值在于统一向量空间，支持 Any-to-Any。
3. 混合检索的价值在于同时覆盖语义召回和关键词召回。
4. Corrective / Adaptive / Human-in-the-loop 体现的是生产系统的可靠性设计。
