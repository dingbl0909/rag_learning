# 实现说明

这个项目对应“基于 GME 模型的安防多模态 RAG 知识库项目系统”。当前代码已经从纯演示链路调整为真实 GME 嵌入接入：系统启动时会加载 `iic/gme-Qwen2-VL-7B-Instruct` 或本地私有化模型目录，对文本、图片、图文对生成统一向量。

## 程序入口

正式 API 入口是 `app/api.py`：

```bash
cd /root/rag_learning/gme_security_multimodal_demo
uvicorn app.api:app --host 0.0.0.0 --port 8012
```

本地命令行验证入口是 `app/run_example.py`：

```bash
python -m app.run_example
```

主链路在 `app/workflow_graph.py`，核心入口是 `MultimodalSecurityGraph.ask()`。API 的 `/ask` 和命令行样例最终都会调用这条 LangGraph 工作流。

## 运行配置

真实 GME 由 `app/config.py` 从环境变量读取配置：

```bash
export GME_MODEL_PATH=/models/gme-Qwen2-VL-7B-Instruct
export GME_DEVICE=cuda
export GME_IMAGE_ROOT=/data/security_multimodal_images
export GME_TRUST_REMOTE_CODE=true
export GME_NORMALIZE_EMBEDDINGS=true
```

- `GME_MODEL_PATH`：私有化模型目录，也可以是 `iic/gme-Qwen2-VL-7B-Instruct`。
- `GME_DEVICE`：推荐 `cuda`，没有 GPU 时可用 `cpu`，但 7B 模型会很慢。
- `GME_IMAGE_ROOT`：知识库 `IMAGE_REF` 和接口 `image_ref` 的图片根目录。
- `GME_TRUST_REMOTE_CODE`：加载 GME 模型时需要开启。
- `GME_NORMALIZE_EMBEDDINGS`：默认归一化向量，便于余弦相似度检索。

更完整的私有化部署步骤见 `docs/gme私有化部署指南.md`。

## 主链路

系统可以按 8 个阶段理解：

1. `parser_demo.py`
   - 读取知识库文档，解析标题、段落、`IMAGE_REF`、`TABLE_REF`、`BASE64_REF`。
2. `chunker_demo.py`
   - 构建 `text` / `image` / `text_image` / `text_table` 知识单元，执行章节切分、语义二次切分和图片 caption 绑定。
3. `embedding_demo.py`
   - 通过 SentenceTransformers 加载私有化 `gme-Qwen2-VL-7B-Instruct`，编码文本、图片和图文对。
4. `index_demo.py`
   - 在本地进程内维护 Dense + Sparse 混合检索结构，对齐 Milvus Dense/Sparse 双索引设计。
5. `memory_demo.py`
   - 维护短期会话、查询缓存和长期语义记忆，对齐 Redis + Milvus 记忆设计。
6. `evaluation_demo.py`
   - 执行 Corrective RAG、Adaptive RAG 和 RAGAS 风格评分。
7. `workflow_graph.py`
   - 编排输入识别、记忆召回、知识检索、CRAG、答案生成、Adaptive 评估、HITL 和记忆落库。
8. `api.py`
   - 提供 `/ask`、`/resume`、`/example` 和健康检查接口。

## 当前真实接入

- GME 嵌入是真实接入：`GMEEmbeddingModel` 使用 `sentence-transformers` 加载 `iic/gme-Qwen2-VL-7B-Instruct`。
- 图片输入是真实读取：`image_ref` 支持绝对路径、`GME_IMAGE_ROOT` 下文件名、原始 Base64、`data:image/...;base64,...`。
- Milvus 是最小生产化接入：`MilvusHybridIndex` 将知识块向量和元数据写入 Milvus，使用 HNSW + COSINE 做 Dense 召回，并保留本地 BM25 作为轻量 Sparse 重排。
- Redis + Milvus 记忆是真实接入：`RedisMilvusMemoryEngine` 用 Redis 保存短期会话和查询缓存，用 Milvus 保存长期语义记忆向量。
- LangGraph 工作流是真实依赖：HITL 使用 `interrupt`，人工审批后通过 `/resume` 继续。
- 查询模式是真实分流：支持 `text`、`image`、`text_image` 三种输入。

缺少模型依赖、模型目录或图片资源时，系统会直接报错，不会静默降级成哈希向量。

## 最小生产单元

本项目现在可以用 Docker Compose 启动 Milvus Standalone、Redis、etcd 和 MinIO：

```bash
cd /root/rag_learning/gme_security_multimodal_demo
docker compose up -d
```

生产化开关默认开启，也可以显式配置：

```bash
export USE_MILVUS=true
export USE_REDIS=true
export MILVUS_URI=http://127.0.0.1:19530
export MILVUS_KB_COLLECTION=security_multimodal_kb
export MILVUS_MEMORY_COLLECTION=security_long_term_memory
export MILVUS_REBUILD_INDEX=true
export REDIS_URL=redis://127.0.0.1:6379/0
```

启动 API 后，`MultimodalSecurityGraph` 会执行：

1. 读取 `data/security_multimodal_docs/*.md`。
2. 解析知识块并调用真实 GME 生成向量。
3. 将知识块写入 Milvus 的 `security_multimodal_kb` 集合。
4. `/ask` 查询时从 Milvus 做 Dense 召回，再用 BM25 和 domain soft boost 重排。
5. 会话短期记忆和查询缓存写入 Redis。
6. 问答结论写入 Milvus 的 `security_long_term_memory` 集合，后续问题可做长期记忆召回。

如果需要临时回到单进程实现，可以设置：

```bash
export USE_MILVUS=false
export USE_REDIS=false
```

## 仍需继续增强

- 当前 Milvus 知识库已接入 Dense HNSW；Sparse 侧仍是本地 BM25 重排，后续可升级为 Milvus Sparse BM25/DAAT 字段。
- 当前长期记忆已写入 Milvus；后续可增加 TTL、用户隔离策略、异步写入和记忆质量过滤。
- `parser_demo.py` 当前读取已结构化 markdown，生产环境应接入 Dots.OCR + vLLM，将 PDF/PPT/Word/HTML 解析成统一中间格式。
- `evaluation_demo.py` 当前是规则化评分，生产环境应接入 RAGAS 离线评测集和线上质量监控。
- `workflow_graph.py` 的 `_compose_answer` 当前是模板生成，生产环境应接入私有化 Qwen3-VL 或其他 LLM 生成答案。

## 关键能力

1. 多模态知识不是只做图片 OCR，而是把文本、图片、图文对统一成可检索知识单元。
2. GME 的核心价值是统一向量空间，支持文搜图、图搜文和图文联合检索。
3. 混合检索同时覆盖语义召回和关键词召回，适合安防手册、告警截图、接口说明和排障案例。
4. Corrective RAG、Adaptive RAG 和 Human-in-the-loop 共同降低安防问答中的幻觉风险。
