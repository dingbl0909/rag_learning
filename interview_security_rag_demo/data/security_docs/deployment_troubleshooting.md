# 部署排障与服务运维

## Milvus 启动后检索为空

若 Milvus 容器启动正常但检索为空，应先确认集合是否完成建表和加载，再检查入库任务是否真正写入向量，同时核对检索使用的集合名、向量维度和索引字段是否一致。很多问题并不是 Milvus 本身不可用，而是写入和查询使用了不同的 schema。

## 容器化部署排查顺序

当 Docker 部署的安防知识系统无法启动时，建议按照容器状态、端口映射、配置文件挂载、依赖服务健康检查和应用日志五个层次进行排查。若是多容器协同时出现超时，应额外检查网络桥接和服务发现配置。

## 向量检索效果差

如果向量检索效果差，应先确认 chunk 是否过短或过长，再检查是否同时保留了关键词检索能力。对于部署手册、接口说明和故障案例类文档，通常推荐采用 Dense + Sparse 混合检索，而不是只依赖单一路径。

## 模型与推理服务排查

当嵌入模型或问答模型响应超时时，应先确认模型服务健康状态，然后检查并发限制、请求超时配置和上游依赖。对需要 OCR 或多模态处理的场景，应单独监控解析服务和向量化服务，避免把所有问题都归因到主模型。
